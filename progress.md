## Known, stated limitations (not gaps hiding as bugs)

- **Contract's request-field agreement is JS/TS only**, and only when both sides are a literal object — Python/Go and response-shape comparison aren't covered yet.
- **Hero-act only catches its 3-pattern catalog** — not a general "was this a real bug" judgment (not resolvable from static snapshots alone), and requires `malveon watch` to have actually been running without a gap. No manual fallback anymore — removed 2026-09-16.
- **Incompleteness is one-directional** — a marker's presence is real proof, its absence proves nothing (most finished code has none either). Never a substitute for the confidence check.
- **Overlap's reachability note is a best-effort heuristic, not real call-graph analysis** — an anonymous handler or a genuinely dead route it can't attribute to a named function still just counts as a plain registration, same as before 2026-09-16.
- **Frontend overlap risk (both Tailwind and plain CSS) is file-scoped, not ancestor-precise** — no real JSX tag-tree or CSS selector-specificity resolution.
- **Confidence check doesn't parse confidence language as standalone evidence** — it only ever cross-references a claim against the wiring verdict, by design.
- **JS `axios({method:'post', url:'/x'})` object-call style, and Flask's bare `@app.route(...)` without an explicit method, aren't parsed** — left `NOT TESTED` rather than guessed.
- **`malveon watch` doesn't work over NFS/SMB** (fsnotify's own constraint) and can fail to start on very large repos if the OS's inotify-watch/file-descriptor limits are hit — surfaced as a real error, never swallowed.
- **The command check never invents a command the project didn't define** — a `tsconfig.json` with no `typecheck` script, or a Python app with no `[build-system]`, correctly stays NO PROOF rather than guessing at `tsc --noEmit` or a build step. "Focused" test scoping (only tests relevant to changed files) isn't built — it runs the project's whole defined test command, honestly.
- **The exit-code gate is all-or-nothing** beyond `--no-gate` — no per-check configuration (e.g. "block on FAIL but not NO PROOF") yet.
